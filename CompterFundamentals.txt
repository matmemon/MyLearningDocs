Phase 3 — Communication patterns
This is especially important for architecture.

4	      Polling	                                Client repeatedly checks for updates

Phase 4 — Communication technologies and alternatives

A. Traditional API communication
REST API / HTTP
For normal application requests and responses.

B. Real-time communication
WebSocket
Persistent two-way communication.
SignalR
Simplifies real-time communication in .NET.
Server-Sent Events (SSE)
Server pushes updates to clients, primarily one-way.

C. Remote procedure and service communication
gRPC
Efficient service-to-service communication, including streaming.

D. Asynchronous messaging
Azure Service Bus / RabbitMQ / Kafka
Backend messaging, buffering and independent processing.

E. Lightweight device messaging
MQTT
Lightweight publish-subscribe messaging, commonly used for IoT.
