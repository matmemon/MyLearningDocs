Track C — Design Principles and Patterns
30 topics · 8 parts · Frozen

Out of scope: Architecture styles and DDD in depth, messaging-product internals, language syntax tutorials, and UI architecture beyond the patterns named.

This track covers pattern intent, structure, implementation choices, consequences and trade-offs—not the full depth of every technology that implements them.

Depth: Master = hands-on; Reason = explain trade-offs; Aware = know it exists.

C19 distinction: Understand the individual purpose of each control. A timeout bounds waiting; retry attempts recovery; a circuit breaker prevents repeated calls to an unhealthy dependency; bulkheads isolate resource pools; rate limiting controls demand. They are complementary, not interchangeable.

C23 distinction: Saga compensation is a new business action that counteracts an earlier action. It is not a database rollback across services.

Learning rule: For Master topics, build two implementations of the same requirement where useful: one straightforward implementation and one using the pattern. Compare complexity, testability, extensibility and runtime behavior. Deliberately overuse a pattern, then refactor it away. For Reason topics, explain the problem, consequences and alternatives.
